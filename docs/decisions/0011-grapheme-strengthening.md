# ADR-0011：组合强化包与 T-MATCH

- **状态**：Accepted
- **日期**：2026-11-11
- **决策者**：P5 实现
- **影响条款**：DESIGN §1.3、§2.1、§3.3、§3.4
- **相关**：`TMatch.js`、`Scheduler.js`、`StateRepository`

## 背景

P5 要补组合（grapheme）独立阶梯与 T-MATCH 配对/分类，避免只在整词里“顺带”练组合。
DESIGN 要求每天最多 1 个组合、2—3 个词，连续正确跨 2 个不同词后进入待抽查。

## 决定

### D1：T-MATCH 做多选分类，不做四选一

- 给一个 focus 组合（如 `sh`）和 4 个词（2—3 个包含、1—2 个不包含）；
- 孩子可多选、可少选、可全不选；提交 `tap-unit` 集合；
- judge 比较选中词集合与正确集合；
- 一次显示全部选项，但不是“单选正确项”，不引入积分/胜负。

### D2：组合状态随整词尝试更新

`Scheduler.recordAttempt` 在写 wordState 后：

- 答对：更新词内全部组合；
  - `wordsPassed` 去重追加 wordId；
  - `nextReview` 升档；
  - 连续正确跨 2 个不同词且达到 3 次 → `status='probe'`；
- 答错：只更新错误画像指向的组合，降档、次日到期；
- 组合 dueDate 与词 dueDate 独立。

### D3：每日最多 1 个组合强化包

- `buildGraphemeDrill` 从 `listDueGraphemes` 取第一个有至少 2 个词例的组合；
- 追加 1 条 T-MATCH spec，队列不超过 8；
- 选项由包含该组合的词（最多 3）与不包含的词（最多 2）组成；
- 选项顺序由 seed 洗牌，可复现。

### D4：UI 只做集合选择

- T-MATCH layout 显示 focus 文本与词按钮；
- 点击切换选中，Check 提交；
- 不显示“正确/错误”选项标签，不提前泄露答案；
- 组合强化仍属于拼写练习的辅助，不是独立课程。

## 后果

- 正面：组合有独立间隔与跨词条件；每日一个强化包；T-MATCH 可点选完成。
- 负面：T-MATCH 是词形分类，不直接要求拼写；作为 P5 强化包可接受。
- 负面：初始没有 graphemeState 时不会生成 T-MATCH；需要先做过整词。
- 约束：组合状态写入只发生在调度层，UI/题型层不写状态。

## 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 四选一“哪个含 sh” | 退化成选择题，违反产品边界 |
| 每天多个组合包 | 违背“每天最多 1 个” |
| 组合状态只按词状态复制 | 无法体现独立阶梯与跨词条件 |
| T-MATCH 只做拖拽配对 | 移动端成本高；点选等价优先 |
