# ADR-0023：单元顺序解锁与练习设计页

- **状态**：Accepted
- **日期**：2026-11-12
- **影响条款**：DESIGN §2.1
- **相关**：`unitProgress.js`、`PracticeSetupScreen.js`、`bootstrap.js`

## 背景

练习设计页原先一次显示当前教材全部 72 个单元，孩子无法判断学习顺序；
用户要求只显示已完成单元和下一个新单元，按顺序解锁。

## 决定

### D1：完成定义

单元完成 = 该单元全部词都至少完成过一次练习（存在 `wordState`）。

- 不要求全部 `mastered`；
- 掌握程度仍由调度器/复习曲线负责；
- 单元进度显示 `practiced/count`。

### D2：可见单元

按 `grade → term(上/下) → unit` 排序：

```text
所有已完成单元 + 第一个未完成单元（Next）
```

后续单元不渲染，直到当前单元完成。

- 已完成单元可复选，用于复习；
- 当前单元默认选中；
- 全部完成时显示全部已完成单元；
- 锁定单元不显示，避免误选。

### D3：进度来源

`readContent` 同时读取 `wordStates`：

```js
unit.practiced = unit 内已有 wordState 的词数
unit.completed = practiced === count
```

切换教材后按当前教材重新计算。

### D4：题量

仍受后台 `questionsPerPractice` 约束；但当前单元词数不足 20 时，
只生成实际可出题数量（例如第 1 单元 6 词 → 6 题），不跨未解锁单元凑数。

## 后果

- 正面：孩子看到清晰的“Done / Next”路径；
- 正面：不会一次看到 72 个单元；
- 正面：完成单元仍可选择复习；
- 负面：早期小单元题量少于 20；
- 负面：完成定义是“练过”而非“掌握”，掌握情况看 Stats。
