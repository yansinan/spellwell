# ADR-0007：按序选择的插入式重排

- **状态**：Accepted
- **日期**：2026-11-11
- **决策者**：P1 交互修订
- **影响条款**：DESIGN §3.4、§6.2
- **相关**：`src/ui/PracticeScreen.js`、`src/ui/sequenceOrder.js`

## 背景

T-SEQUENCE 已支持从待选区拖入槽位。反馈进一步要求：

- 已经到位的块仍然可以拖拽调整位置；
- 拖到另一个块上方时，按左右相对位置决定插到它前面还是后面；
- 后面的块相应左移/右移，而不是简单覆盖目标槽位。

如果继续用“固定 slotIndex + 覆盖”模型，会出现：

- 已放置块不能移动；
- 拖到第二个块上会替换它，而不是插入；
- 出现空洞或重复单位；
- Check 可用性与实际顺序不一致。

## 决定

### D1：有序列表是唯一真相

T-SEQUENCE 的已选单位表示为连续有序列表；`slotIndex` 只是渲染位置：

```text
[f, i, sh]  // slotIndex 0,1,2
```

点击选中追加到末尾；点击已填槽移除并压实；已使用的灰色待选块禁用；拖拽重排后重新编号，不留下空洞。

### D2：落点由目标槽位的左右半边决定

指针落在目标槽位的左半边 → 插到目标之前；右半边/中心 → 插到目标之后：

```text
boundary = targetSlotIndex + (x >= targetCenterX ? 1 : 0)
```

槽位 64px 吸附半径内才视为有效目标；远端释放按未命中处理。

### D3：移动已选块时先移除、再按边界插入

设源下标为 `s`，原始边界为 `b`：

1. 从列表中移除源块；
2. 若 `b > s`，边界减 1（因为移除发生在边界之前）；
3. clamp 到 `[0, list.length]` 后插入。

覆盖的典型情况：

| 操作 | 结果 |
|---|---|
| `[f,i,sh]` 把 `f` 拖到 `sh` 右半边 | `[i,sh,f]` |
| `[f,i,sh]` 把 `sh` 拖到 `f` 左半边 | `[sh,f,i]` |
| `[f,i,sh]` 把 `i` 拖到 `i` 左/右半边 | 不变 |
| `[f,i,sh]` 把 `f` 拖到 `i` 右半边 | `[i,f,sh]` |

### D4：满槽时拒绝新候选块，不覆盖

- 已选块移动：移除后长度减一，必然有位置，允许插入；
- 新候选块：槽位已满时返回拒绝，浮层按“未命中”弹回，原顺序不变；
- 不把“拖到已占槽位”解释为替换；替换会让其他块意外消失，不符合顺序学习目标。

### D5：点击与拖拽共用同一有序模型

- 点击待选区块：追加到末尾；
- 点击已填槽：移除该单位，后面的块左移；已使用的待选块置灰禁用；
- 拖拽待选区块：插入；
- 拖拽已填槽：移动；
- Check 只在列表长度等于目标单位数时启用；提交时重新编号为连续 `slotIndex`。

### D6：拖拽中实时侧滑预览，释放才提交

- `previewInsertUnit()` 返回当前槽位到预览槽位的 `moves` 与 `insertAt`；
- 源块视觉隐藏，其他块用 `translateX` 平移让位，插入点显示虚线缺口；
- 槽位元素只改 inline `transform` / `opacity`，**不修改 `#events`**；
- 离开所有槽位或弹回时清除预览并还原；
- 释放命中后才调用 `#insertUnit` 提交，并重新渲染连续 `slotIndex`。

## 后果

- 正面：重排语义可预测；左右插入符合直觉；不会产生覆盖/空洞；纯逻辑可单测。
- 负面：拖拽中有平滑侧滑，但释放提交仍是一次重渲染，没有跨回合 FLIP；P8 可继续优化。
- 成本：`PracticeScreen` 的 `#events` 必须始终连续；`slotIndex` 不再代表固定物理位置，而是当前顺序。

## 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 拖到已占槽位就替换 | 目标块消失，顺序练习变成替换练习 |
| 只在拖到空槽才允许移动 | 无法把块插到其他块前面/后面 |
| 保留空洞 slotIndex | 判定、Check、焦点都会混乱 |
| 用 HTML5 native drag | 移动端不可用，且无法稳定控制落点左右 |
| 满槽时静默丢弃候选块 | 孩子会以为块丢了，必须弹回并保留原状态 |
