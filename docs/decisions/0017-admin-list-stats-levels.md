# ADR-0017：后台列表按 level 折叠，显示错/对次数

- **状态**：Accepted
- **日期**：2026-11-11
- **决策者**：后台交互修订
- **影响条款**：DESIGN §2.3
- **相关**：`AdminApp.js`、`AttemptStats.js`

## 背景

后台单词列表原先把内部 ID 放在每个词下面，对内容维护者意义低；所有词平铺，找词慢。
用户要求：

1. ID 改为“错误次数 / 正确次数”；
2. 按 level 分组并可折叠；
3. level 用更直观的教学标签（如“1 单元 · 一年级下学期”）。

## 决定

### D1：列表主信息改为学习统计

- 每个词显示：词/中文、`错 N / 对 M`、未保存标记；
- 不显示内部 `w.*` ID（编辑区仍显示，用于稳定引用）；
- 统计来自 `attempts` 的只读聚合，按 `wordId` 计数；
- 新词默认 `错 0 / 对 0`。

### D2：level 分组 + 折叠

- `level=1` 显示为 `1 单元 · 一年级下学期`；
- `level=2` 显示为 `2 单元 · 二年级上学期`；
- 使用原生 `<details>`，可折叠；选中词所在组自动展开；
- 搜索时自动展开匹配组，并隐藏无匹配组。

### D3：统计只读

- AdminApp 可 `adapter.query('attempts', {})` 聚合；
- 不写 attempts / wordStates / graphemeStates；
- 不 import StateRepository/AttemptRepository；
- 架构守卫从“不得出现 attempts”改为“不得写入 attempts”。

## 后果

- 正面：列表直接体现学习情况；按教学单元分组，找词更快。
- 正面：内部 ID 不再占据用户注意力。
- 负面：level 标签目前在 AdminApp 中硬编码，后续可配置到内容元数据。
- 负面：attempts 全量读取；当前数据量小，未来需分页/索引聚合。

## 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 继续显示 ID | 对内容编辑无帮助 |
| 平铺列表 | 词量增长后难找 |
| 显示正确率百分比 | 低样本会误导，错/对次数更直观 |
| 后台写统计缓存 | 越权写学习状态 |
