## 3. 数据质量发现

| 问题 | 数量/事实 | 影响 |
|---|---|---|
| 全部未审核 | 583/583 `unreviewed` | 生产导出被 V10 阻断，必须先审核 |
| 缺音标 | 10 个 | 提示词会降级到中文/单词 |
| 缺句子 | 只有 4 个句子关联 | 句子提示几乎不可用，主要靠音标/中文 |
| 单元过小 | 15 个单元少于 5 词，最小 1 词 | 单 unit 练习达不到默认 20 题 |
| 单/双字母词 | 17 个（i/is/my/it/do/no/on/in/he/or/go/to/at/pe/we/ok/so） | 拼写过易，会拉低练习密度 |
| 超长单词 | 3 个 13—14 字母 | 已把内容规范从 12 放宽到 15 |
| 跨年级重复 | 94 条重复单单词条目 | 当前去重会丢失“同一词在不同单元/年级出现”的课程关系 |
| 自动切分 | 平均 4.25 块/词，最多 10 块 | 部分切分只是字母保底，不一定教学最优 |

## 4. 建议优化优先级

### P0：先审核，再发布

- 583 个词全部 `unreviewed`；
- 先审核高频词、低年级词、核心名词/动词；
- 审核后再允许 `reviewed` 导出，避免把自动切分直接给孩子。

### P1：补音标和句子

- 10 个缺音标优先补齐；
- 当前只有 4 句，建议至少给每个 unit 的 core words 配 1 句；
- 提示词优先级已经实现：句子 → 音标 → 中文 → 单词。

### P2：单元模型升级为多对多

当前一个词只能属于一个 unit，导致 94 条跨单元重复被折叠，部分 unit 只剩 1—2 词。
建议：

```json
"unitRefs": [
  { "grade": 1, "term": "下", "unit": 2 },
  { "grade": 2, "term": "上", "unit": 1 }
]
```

练习按 `unitRefs` 过滤；后台可按课程位置审核。这样既不重复词条，也不丢课程关系。

### P3：拆出“课程位置”和“拼写难度”

- 课程位置：grade/term/unit；
- 拼写难度：长度、grapheme 数、歧义组合、是否有 silent e；
- 不要把“一年级上”直接当作“拼写简单”；
- 单/双字母词应进入低难度或作为热身，不应占满 20 题。

### P4：切分质量

- 当前自动切分只是最长匹配；
- 优先人工复核：`igh/eigh/ough/augh`、r-controlled、silent e、双写辅音；
- 对 3 字母以上单词检查是否出现“纯字母保底”切分；
- 后台可增加“切分可信度”标记。

### P5：题库与内容量适配

- 583 词/72 unit，默认 20 题；
- 15 个 unit 不足 5 词，前台按实际词数出题；
- 练习设计支持多 unit 合并；
- 后台单元树需要搜索/折叠/分页，否则 72 组列表会变长。

### P6：数据工作流

- 词库 JSON 已支持单独导入/导出；
- 建议增加“审核状态/来源/版本”字段，避免下次换教材版本时覆盖人工审核；
- 词库导入按稳定 ID 合并，保留人工切分和审核状态。

## 5. 结论

基础词库已经可以用于开发、分单元练习和发音/中文提示验证；
但它仍是**未审核自动标注数据**，不适合直接作为生产内容发布。
下一步最值得做的是：

1. 补音标和句子；
2. 把 unit 改成多对多课程位置；
3. 审核高频词切分；
4. 对单/双字母词做难度分层；
5. 后台单元树加搜索/分页。
